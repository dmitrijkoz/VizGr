# Визуализатор графа зависимостей пакетов(10 вариант)

## Этап 2. Сбор данных

### Описание проекта

Приложение предназначено для получения информации о зависимостях пакетов JavaScript из реестра npm.

На втором этапе реализовано получение метаданных выбранного пакета, определение его последней опубликованной версии и извлечение прямых зависимостей.

Для получения информации используется HTTP API npm Registry. Менеджеры пакетов и сторонние библиотеки для извлечения зависимостей не используются.

### Требования

- Python 3.10 или новее.
- Доступ к интернету для обращения к npm Registry.
- Реестр npm, доступный по HTTP или HTTPS.

Дополнительные Python-библиотеки не требуются.

### Реализованные возможности

1. Получение имени анализируемого пакета из аргументов командной строки.
2. Настройка URL реестра npm.
3. Проверка режима работы с репозиторием.
4. Получение метаданных пакета по HTTP.
5. Определение последней версии пакета по тегу `latest`.
6. Извлечение прямых зависимостей из поля `dependencies`.
7. Сортировка зависимостей по имени.
8. Фильтрация зависимостей по подстроке.
9. Обработка HTTP-ошибок, проблем сети и некорректных JSON-данных.
10. Вывод найденных зависимостей в терминал.

### Запуск приложения

Откройте терминал в корневом каталоге проекта.

Для получения прямых зависимостей пакета `express` выполните:

```bash
py main.py --package express --repository https://registry.npmjs.org --test-repo-mode remote --max-depth 2
```

Приложение получит данные из npm Registry и выведет версию пакета и список его прямых зависимостей.

### Параметры командной строки

| Параметр | Описание |
|---|---|
| `--package` | Имя анализируемого npm-пакета |
| `--repository` | URL реестра npm |
| `--test-repo-mode` | Режим работы с источником данных |
| `--max-depth` | Максимальная глубина анализа, сохраняемая в конфигурации |
| `--filter` | Необязательная подстрока для фильтрации имён зависимостей |

Пример с фильтрацией:

```bash
py main.py --package express --repository https://registry.npmjs.org --test-repo-mode remote --filter cookie
```

В этом случае будут показаны только зависимости, в именах которых содержится подстрока `cookie`, без учёта регистра.

### Пример результата

Фактический список зависит от версии пакета, опубликованной в npm Registry.

```text
Параметры запуска:
package=express
repository=https://registry.npmjs.org
test_repo_mode=remote
max_depth=2
package_filter=(не задан)
resolved_repository_mode=remote

package_version=<версия пакета>

Прямые зависимости: <количество>
<имя зависимости> = <диапазон версий>
```

### Источник данных

Используется публичный npm Registry:

https://registry.npmjs.org/

Метаданные пакета запрашиваются по адресу:

```text
https://registry.npmjs.org/<имя-пакета>
```

Для пакетов с областью видимости, например `@scope/package`, имя кодируется для использования в URL.

Версия выбирается по тегу `latest`. Прямые зависимости извлекаются из объекта `dependencies` соответствующей версии.

### Обработка ошибок

Приложение обрабатывает следующие ситуации:

- Некорректный URL реестра.
- Отсутствие указанного пакета.
- HTTP-ошибки реестра.
- Недоступность сети или превышение времени ожидания.
- Некорректный JSON в ответе сервера.
- Отсутствие тега `latest` или некорректные метаданные версии.
- Некорректный формат поля `dependencies`.
- Ошибки конфигурации командной строки.

При ошибке выводится диагностическое сообщение в `stderr`, а приложение завершается с кодом `2`.

### Ограничения второго этапа

- Получаются только прямые зависимости выбранной версии пакета.
- Транзитивные зависимости не анализируются.
- Граф зависимостей пока не строится и не визуализируется.
- Параметр `--max-depth` сохраняется для совместимости с конфигурацией, но на этом этапе не влияет на получение данных.
- Поля `devDependencies`, `peerDependencies` и `optionalDependencies` отдельно не обрабатываются.
