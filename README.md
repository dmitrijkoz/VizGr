# Визуализатор графа зависимостей пакетов (вариант 10)

## Этап 3. Основные операции

### Назначение

Приложение строит граф прямых и транзитивных зависимостей npm-пакета.
Обход выполняется алгоритмом BFS с рекурсивной обработкой уровней графа.
Для тестирования можно вместо npm Registry передать локальный JSON-файл.

Получение зависимостей из npm Registry реализовано стандартными средствами
Python (`urllib` и `json`); менеджеры пакетов и библиотеки для анализа
зависимостей не используются.

### Требования

- Python 3.10 или новее.
- Для удалённого режима необходим доступ к `https://registry.npmjs.org`.
- Дополнительные Python-библиотеки не требуются.

### Параметры командной строки

| Параметр | Назначение |
| --- | --- |
| `--package NAME` | Имя корневого пакета, для которого строится граф |
| `--repository URL_OR_PATH` | URL npm Registry или путь к JSON-файлу |
| `--test-repo-mode MODE` | Режим: `auto`, `local` или `remote` |
| `--max-depth N` | Максимальная глубина: `0` — только корневой пакет |
| `--filter SUBSTRING` | Исключает зависимые пакеты, содержащие подстроку |

Режим `auto` выбирает источник автоматически: HTTP(S)-адрес означает удалённый
реестр, путь к файлу — локальный тестовый репозиторий.

### Алгоритм построения графа

1. Корневой пакет помещается в первый уровень обхода.
2. Для всех пакетов текущего уровня запрашиваются прямые зависимости.
3. Из списка удаляются имена, содержащие фильтрующую подстроку
   (сравнение без учёта регистра).
4. Новые пакеты добавляются в следующий уровень. Уже посещённые пакеты
   повторно в очередь не помещаются.
5. Следующий уровень обрабатывается рекурсивным вызовом функции обхода.
6. Обход завершается после достижения `--max-depth` или исчерпания очереди.

Такой порядок сохраняет свойства BFS: сначала обрабатываются все вершины
одинаковой глубины. Множество `visited` не позволяет зациклить обход при
циклических зависимостях. Ребро, замыкающее цикл, остаётся в результирующем
графе, но повторная обработка вершины не выполняется.

Глубина считается от корневого пакета: глубина корня равна 0, его прямых
зависимостей — 1. Корневой пакет сохраняется в графе как точка анализа,
даже когда его имя совпадает с фильтром; фильтр применяется к зависимостям.

### Запуск в локальном тестовом режиме

В PowerShell или терминале из корневой папки проекта выполните:

```powershell
py main.py --package A --repository test-repository.json --test-repo-mode local --max-depth 3
```

Пример с ограничением глубины:

```powershell
py main.py --package A --repository test-repository.json --test-repo-mode local --max-depth 1
```

Пример с фильтром, исключающим пакет `D` и все его появления в списках
зависимостей:

```powershell
py main.py --package A --repository test-repository.json --test-repo-mode local --max-depth 3 --filter D
```

### Демонстрация разных случаев

**1. Ветвление и общая транзитивная зависимость**

```powershell
py main.py --package A --repository test-repository.json --test-repo-mode local --max-depth 3
```

Граф содержит ветви `A -> B`, `A -> C`; обе ветви ведут к общей вершине `D`.
Повторно `D` обрабатываться не будет.

**2. Циклические зависимости**

```powershell
py main.py --package A --repository test-repository-cycle.json --test-repo-mode local --max-depth 10
```

В файле задан цикл `A -> B -> C -> A`. Приложение сохранит циклическое ребро,
но завершит обход без бесконечного повторения пакетов.

**3. Линейная цепочка и ограничение глубины**

```powershell
py main.py --package A --repository test-repository-linear.json --test-repo-mode local --max-depth 2
```

В граф попадут `A`, `B`, `C`; зависимости `C` дальше анализироваться не будут.

### Удалённый режим npm

```powershell
py main.py --package express --repository https://registry.npmjs.org --test-repo-mode remote --max-depth 2
```

Для каждого обнаруженного пакета запрашиваются метаданные npm Registry.
Используется версия с тегом `latest`, а список прямых зависимостей читается
из поля `dependencies` этой версии.

### Формат тестового репозитория

Файл должен содержать объект JSON со списком `packages`. Имена пакетов и
зависимостей — последовательности больших латинских букв `A-Z`. Все указанные
зависимости должны существовать среди пакетов файла.

```json
{
  "repository_name": "example",
  "packages": [
    {"name": "A", "dependencies": ["B"]},
    {"name": "B", "dependencies": []}
  ]
}
```

### Обработка ошибок

Приложение сообщает об ошибке и завершает работу с кодом `2`, если параметры
командной строки некорректны, файл недоступен, JSON повреждён, имена пакетов
не соответствуют формату `A-Z`, зависимость ссылается на отсутствующий пакет,
пакет не найден в локальном репозитории или npm Registry недоступен.

### Запуск тестов

```powershell
py -m unittest discover -s tests -v
```

Тесты проверяют порядок BFS, транзитивные связи, глубину `0` и `1`, фильтр,
циклические зависимости, повторные рёбра, формат тестового JSON и валидацию
параметров.
